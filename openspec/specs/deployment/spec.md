# deployment

## Purpose

Описывает наблюдаемое поведение доставки приложения в продакшен: где доступна
опубликованная версия, когда она обновляется и как ведут себя прямые ссылки на
внутренние маршруты.

## Requirements

### Requirement: Публикация продакшен-версии на GitHub Pages

Продакшен-версия приложения SHALL раздаваться GitHub Pages по адресу
`https://krasotun.github.io/messenger/` по HTTPS. Раздача статики MUST NOT
зависеть от отдельного арендованного сервера, SSH-доступа или ручной настройки
веб-сервера.

#### Scenario: Открытие корневого адреса

- **WHEN** пользователь открывает `https://krasotun.github.io/messenger/`
- **THEN** отдается опубликованная сборка приложения, и статические ресурсы (скрипты, стили, изображения) загружаются без ошибок 404

#### Scenario: Обращение по HTTP

- **WHEN** запрос приходит по `http://`
- **THEN** он перенаправляется на `https://`

### Requirement: Автоматический деплой после успешных проверок

Публикация SHALL выполняться автоматически при попадании коммита в `main` и
по ручному запуску workflow. Артефакт MUST публиковаться только после успешного
прохождения линтера, unit-тестов, e2e-тестов и сборки.

#### Scenario: Коммит попал в main

- **WHEN** изменение смержено в `main` и все проверки качества прошли
- **THEN** собранный артефакт публикуется на GitHub Pages, и по продакшен-адресу доступна версия из этого коммита

#### Scenario: Проверки качества не прошли

- **WHEN** линтер, unit-тесты, e2e-тесты или сборка завершаются с ошибкой
- **THEN** публикация не выполняется и по продакшен-адресу остается предыдущая рабочая версия

#### Scenario: Ручной запуск деплоя

- **WHEN** разработчик запускает deploy workflow вручную
- **THEN** выполняется тот же путь проверок и публикации, что и для коммита в `main`

### Requirement: Прямые ссылки на внутренние маршруты

Приложение SHALL корректно открываться по прямой ссылке на любой маршрут SPA,
несмотря на отсутствие серверного fallback у статического хостинга.

#### Scenario: Прямая ссылка на страницу входа

- **WHEN** пользователь открывает `https://krasotun.github.io/messenger/sign-in` напрямую или перезагружает эту страницу
- **THEN** приложение загружается и отображает страницу входа, а не страницу ошибки хостинга

#### Scenario: Неизвестный маршрут

- **WHEN** пользователь открывает адрес, которому не соответствует ни один маршрут приложения
- **THEN** загружается приложение и применяется его собственная маршрутизация, а не страница ошибки хостинга

### Requirement: Работа входа после смены origin

После переезда пользовательские сценарии identity-access SHALL продолжать
работать против продакшен-API `https://ya-praktikum.tech/api/v2` с cookie-сессией.

#### Scenario: Вход с продакшен-адреса

- **WHEN** пользователь входит в аккаунт на опубликованной версии
- **THEN** сессия восстанавливается и защищенные маршруты становятся доступны
