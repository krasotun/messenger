# core-http

## Purpose

Правила обращения приложения к внешнему API, общие для всех доменов: сколько
времени приложение готово ждать ответ и что видит вызывающая сторона, когда
ответа так и не дождались.

## Requirements

### Requirement: Предел времени на запрос к внешнему API

Каждый запрос к внешнему API SHALL иметь предел времени. Ответ, не пришедший за
отведенное время, MUST прерывать запрос: приложение перестает его ждать и не
принимает его результат, если тот придет позже.

#### Scenario: Ответ пришел в отведенное время

- **WHEN** внешнее API отвечает раньше, чем истек предел времени
- **THEN** вызывающая сторона получает результат запроса, как если бы предела не было

#### Scenario: Ответ не пришел в отведенное время

- **WHEN** внешнее API не ответило за отведенное время
- **THEN** запрос прерывается, а вызывающая сторона получает **Ошибку приложения**

#### Scenario: Форма отмирает по истечении предела

- **WHEN** отправка формы не уложилась в предел времени
- **THEN** **Флоу отправки** переходит в состояние ошибки, поле формы и кнопка отправки снова доступны

#### Scenario: Поздний ответ после истечения предела

- **WHEN** внешнее API отвечает уже после того, как предел истек и ошибка показана
- **THEN** этот ответ не влияет на состояние приложения: показанная ошибка остается, результат запроса не появляется

### Requirement: Сообщение об истечении предела доходит до человека

Ошибка от истечения предела времени SHALL нести собственное сообщение о том,
что запрос не уложился во время. Вызывающая сторона MUST показывать это
сообщение, а не свое сообщение об отказе вообще.

#### Scenario: Истечение предела при Входе

- **WHEN** запрос **Входа** не уложился в предел времени
- **THEN** человек видит сообщение о том, что запрос не уложился во время, а не общее сообщение о неудавшемся **Входе**

#### Scenario: Внешнее API отказало по существу

- **WHEN** внешнее API ответило отказом и указало причину
- **THEN** человек видит причину из ответа, как и до появления предела времени

### Requirement: Собственный предел времени для отдельного запроса

Запрос, которому обычного предела заведомо мало, SHALL иметь возможность
объявить собственный. **Смена аватара** MUST пользоваться увеличенным пределом:
она передает файл, и ее длительность законно больше длительности обычного
вызова.

#### Scenario: Загрузка аватара дольше общего предела

- **WHEN** запрос **Смены аватара** идет дольше общего предела времени, но укладывается в свой собственный
- **THEN** запрос не прерывается и **Аватар** заменяется на новый

#### Scenario: Загрузка аватара не уложилась и в собственный предел

- **WHEN** запрос **Смены аватара** не уложился в собственный предел времени
- **THEN** запрос прерывается, а человек видит сообщение о том, что запрос не уложился во время
