# Чаты: список, создание и добавление участника

Issue: #83

## Why

Домен переписки в приложении отсутствует целиком: после **Входа** пользователь
попадает на заглушку «You are signed in». Внешнее API отдает **Чаты** одним
запросом вместе с последним сообщением и счетчиком непрочитанных, без
WebSocket, поэтому полезный экран можно собрать до того, как появится сама
переписка.

Отдельно от списка эта работа смысла не имеет: созданный **Чат** негде
увидеть, а **Добавление участника** нечем проверить.

## What Changes

- Появляется домен `chats` со слоями application, infrastructure и
  presentation.
- Список **Чатов** занимает маршрут `/`; страница-заглушка `home-page` и ее
  спека удаляются.
- **Выбранный чат** задается маршрутом `/:chatId`; рядом со списком
  показывается его шапка, область переписки остается заглушкой.
- **Текущий пользователь** создает **Чат**, указав название.
- **Текущий пользователь** выполняет **Поиск пользователя** по началу
  **Логина** и **Добавление участника** в **Выбранный чат**.
- Шапка **Выбранного чата** показывает **Участников чата**.
- `resolveAvatarUrl` переезжает из `identity-access/infrastructure` в `shared`:
  чужие **Аватары** появляются впервые, и правило нужно обоим доменам.
- `identity-access` отдает наружу use case поиска **Пользователей**; сам
  `USER_GATEWAY` наружу не уезжает.

Не входит: переписка и отправка сообщений, WebSocket, фильтрация **Чатов** по
названию, удаление **Участника чата**, отдельный экран состава **Чата**,
архивация и удаление **Чата**.

## Capabilities

### New Capabilities

- `chats`: список **Чатов** **Текущего пользователя**, создание **Чата**,
  **Выбранный чат** и его шапка, **Поиск пользователя** и **Добавление
  участника**.

### Modified Capabilities

- `identity-access`: у домена появляется **Поиск пользователя** - поведение,
  которого в спеке нет; наружу отдается use case, а не шлюз.

## Impact

Слои: application, infrastructure, presentation нового домена `chats`;
application и infrastructure `identity-access` (**Поиск пользователя**); core
(маршруты, удаление `home-page`); shared (переезд `resolveAvatarUrl`).

Внешнее API: `GET /chats`, `POST /chats`, `PUT /chats/users`,
`GET /chats/{id}/users`, `POST /user/search`. Те же endpoint'ы добавляются в
`mock-auth-backend` и сбрасываются в `POST /test/reset`.

Зависимости не добавляются. Ломающих изменений нет: `home-page` - заглушка без
поведения.
