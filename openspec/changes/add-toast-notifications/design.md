## Context

Мотивация - `proposal.md`, требования - `specs/`. Здесь только то, что
формирует подход.

Ограничения, которые уже стоят в проекте:

- ESLint запрещает слою use case импортировать `@shared/ui/*`, `@angular/cdk`
  и `@angular/platform-browser`. Показ **Уведомления** из этого слоя возможен
  только через контракт, лежащий вне `shared/ui`.
- Прецедент оверлея в проекте один и тот же у `ModalService` и
  `PopoverCoordinator`: CDK `Overlay` + `ComponentPortal`, сервис в
  `shared/ui`. Свои примитивы на CDK - решенный вопрос, см.
  [ADR 2026-06-05](../../../docs/adr/2026-06-05-own-ui-primitives-on-cdk.md).
- Текст **Ошибки приложения** уже готов к показу: `mapHttpError` кладет в
  `ApplicationError.message` либо `reason` от внешнего API, либо fallback от
  вызывающего use case.
- `GlobalPositionStrategy` в установленной версии CDK умеет `top()` и
  `right()` - проверено по `node_modules/@angular/cdk/types/overlay.d.ts`.

## Goals / Non-Goals

**Goals:**

- Один канал исхода для действий, начатых откуда угодно, включая те, после
  которых запустивший элемент исчезает.
- Слой use case, который сообщает об исходе, не зная ни про DOM, ни про
  Overlay.
- Убрать из слоя use case состояние, которое после переезда никто не читает.

**Non-Goals:**

- Очередь **Уведомлений** сверх видимого предела: четвертое вытесняет самое
  старое, а не встает в ожидание.
- Действие внутри **Уведомления** («Отменить», «Повторить»).
- Пауза угасания при наведении курсора.

## Decisions

### Порт вместо подписки со стороны экрана

Решение вынесено в
[ADR 2026-09-06](../../../docs/adr/2026-09-06-use-cases-report-outcome-through-a-notifier-port.md).

### Вводимые сущности

| Имя                | Ответственность                                                         | Слой                   |
| ------------------ | ----------------------------------------------------------------------- | ---------------------- |
| `NotificationKind` | Вид **Уведомления**: успех или ошибка                                   | `shared/notifications` |
| `Notification`     | Вид, заголовок и текст одного **Уведомления**                           | `shared/notifications` |
| `Notifier`         | Контракт показа: сообщить об успехе, сообщить об ошибке                 | `shared/notifications` |
| `NOTIFIER`         | Токен, через который слой use case получает `Notifier`                  | `shared/notifications` |
| `ToastService`     | Реализация `Notifier`: держит стек, владеет overlay и таймерами         | `shared/ui/toast`      |
| `ToastStack`       | Контейнер стека: раскладывает **Уведомления**, объявлен как live region | `shared/ui/toast`      |
| `Toast`            | Одно **Уведомление**: вид, заголовок, текст, кнопка закрытия            | `shared/ui/toast`      |

Каталог `shared/notifications` заводится отдельно от `shared/ui` именно
потому, что слою use case запрещен `@shared/ui/*`. Реализация подключается
провайдером в `app.config.ts` - там же, где живут остальные токены приложения.

### Один overlay на весь стек, а не по overlay на уведомление

`ToastService` держит один `OverlayRef` с `ToastStack` внутри и сигналом
списка **Уведомлений**. Альтернатива - отдельный overlay на каждое
**Уведомление** - потребовала бы считать координаты каждого руками; при одном
контейнере раскладку делает обычный поток.

Overlay создается лениво при первом **Уведомлении** и уничтожается, когда стек
опустел. Это дает нужный порядок наложения: overlay тоста создается позже
overlay модалки, а CDK кладет их в один контейнер, где выше тот, кто добавлен
последним. Никакого ручного `z-index` не требуется.

Позиция - `global().top().right()`, `hasBackdrop: false`: **Уведомление**
ничего не блокирует и не перехватывает клики мимо себя.

### Интервал угасания задает вызывающий, дефолт - 5 секунд

`Notifier` принимает необязательный интервал в каждом вызове; не задан -
берется константа `DEFAULT_NOTIFICATION_DELAY_MS = 5000` из
`shared/notifications`. Альтернатива - DI-токен на приложение - прячет
интервал от того, кто показывает **Уведомление**, и заставляет тест поднимать
провайдер, чтобы проверить угасание. Константа рядом с контрактом дает то же
единое значение по умолчанию без лишнего слоя.

Из этого следует, что интервал у видов может различаться: спека фиксирует
только дефолт, а не равенство интервалов успеха и ошибки.

### Цвета видов берутся из токенов приложения

Успех - `--color-success`, ошибка - `--color-danger`; своих цветов примитив не
заводит. Цвет дублируется заголовком: вид читается и без него. Макет -
[канвас уведомлений от 2026-09-06](https://claude.ai/code/artifact/3685f074-d9ec-4933-b832-bd20fb2d5ace).

### Таймер живет в компоненте одного уведомления

Каждый `Toast` заводит свой таймер на своем интервале и сообщает наружу, что
пора убрать именно его. Альтернатива - общий таймер в сервисе - потребовала
бы хранить время появления каждого и просыпаться по ближайшему; выигрыша нет, а сценарий
«соседние **Уведомления** гаснут независимо» реализуется сам собой.

### Заголовок формирует вызывающий, а не примитив

`Notifier` принимает готовые заголовок и текст. Примитив не знает, что бывает
**Смена пароля**, и не хранит словарь сообщений. Успех: заголовок - действие
(«Смена пароля»), текст - подтверждение («Пароль успешно изменен»). Ошибка:
заголовок - неудача действия («Не удалось сменить пароль»), текст - сообщение
из **Ошибки приложения**.

### Что уходит из слоя use case

Из `createAuthFlowState` и сервисов `add-chat-user`, `create-chat` уходит
сигнал с текстом ошибки; статус отправки остается - он блокирует кнопку и
закрывает модалку. `ChatListService` и `ChatUsersService` не трогаем: их
сообщение об ошибке остается на экране рядом с кнопкой повтора.

### Уровни тестов

| Сценарий из спеки                                                                                 | Уровень       |
| ------------------------------------------------------------------------------------------------- | ------------- |
| Показ поверх приложения, поверх модалки, фокус не переносится                                     | component     |
| Состав **Уведомления**, различие видов                                                            | component     |
| Стек: предел, порядок, вытеснение, повтор с тем же текстом                                        | component     |
| Угасание, закрытие кнопкой, независимость соседей                                                 | component     |
| Объявление скринридером (live region в разметке)                                                  | component     |
| Показ **Уведомления** из слоя use case                                                            | application   |
| Исход **Входа**, **Регистрации**, **Редактирования профиля**, **Смены пароля**, **Смены аватара** | application   |
| Исход **Создания чата** и **Добавления участника**                                                | application   |
| Сообщение об ошибке не остается в форме                                                           | component     |
| Внешний вид стека                                                                                 | e2e `@visual` |

Слои `infrastructure` и `guard` не затрагиваются - тестов этих уровней change
не добавляет.

### Визуальный тест

Один тест с тегом `@visual` снимает стек из двух **Уведомлений** - успех и
ошибка. Требование конвенции «состояния с текстом от бэкенда не снимать»
выполняется тем, что текст берется из детерминированного ответа
`mock-backend`, а не из живого внешнего API.

## Risks / Trade-offs

- Кнопка закрытия **Уведомления** недостижима с клавиатуры, пока открыто
  модальное окно: focus trap CDK не выпускает фокус наружу → **Уведомление**
  гаснет само, кнопка остается ускорением для мыши. Записано осознанно, в
  объем change не входит.
- **Уведомление**, показанное до открытия модалки, окажется под ней: overlay
  модалки добавится позже → живет 5 секунд, а модалки открываются по действию
  человека, не сами. Мириться дешевле, чем управлять `z-index` руками.
- Правый верхний угол пересекается с меню текущего пользователя в шапке →
  отступ сверху разводит стек и шапку.
- Скринридер получает `polite` на оба вида: ошибка прозвучит позже, чем могла
  бы → разделение на `polite` и `assertive` вынесено за объем осознанно
  (`proposal.md`).
- Из семи сервисов уходит публичный сигнал с текстом ошибки - у кого-то из
  них он мог читаться в тестах → тесты правятся в том же блоке, что и сервис.
