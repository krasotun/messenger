## Context

Мотивация - в `proposal.md`, требования - в дельте `specs/chats/spec.md`.

Что ограничивает подход:

- Внешнее API: `GET /chats` принимает необязательные `offset`, `limit` и
  `title` («Chat's title to filter by»). Как именно `title` сравнивается с
  названием (начало, подстрока, регистр), контракт не говорит; значений по
  умолчанию у `limit` и `offset` нет. Методов, которые находят **Чаты** вне
  состава **Текущего пользователя**, в контракте нет.
- Шапка **Выбранного чата** берет **Чат** из `ChatListService.chats()`
  (`selected-chat-header.ts`). Поэтому основной список сужать нельзя: шапка
  потеряла бы название, **Аватар** и право на **Удаление чата**.
- В домене уже есть образец поиска по мере ввода: **Поиск пользователя** -
  `SearchUsersService` (тонкий use case) и `createUserSearchState` (задержка
  300 мс, `switchMap`, отказ схлопывается в «никого не нашли»).
- `Popover` из `shared/ui` рендерит панель через CDK Overlay в контейнер в
  конце `body` (`@angular/cdk/fesm2022/_overlay-module-chunk.mjs`,
  `_createContainer`) и переключается щелчком по хосту. Закрывает его Escape
  (CDK слушает `keydown` на `body`, то есть и при фокусе в поле) и щелчок вне,
  из которого исключен хост; `PopoverCoordinator` держит открытой одну
  панель. Своей спеки у `Popover` нет, до этого change его поведение
  описывали только `popover.spec.ts`.
- Панель списка **Чатов** фиксированной ширины 320px, поле с отступами 16px
  занимает 288px.

## Goals / Non-Goals

**Goals:**

- **Поиск чата** устроен так же, как **Поиск пользователя**: тот, кто знает
  один, читает второй без подготовки.
- Основной список **Чатов** и все, что от него зависит, поиском не
  затрагиваются.
- Выпадающий список переиспользует `Popover`, а не заводит второй механизм
  панелей.

**Non-Goals:**

- Общий примитив «поиск с выпадающим списком» в `shared/ui` и общая фабрика
  состояния поиска - см. решения ниже.
- Выбор найденного **Чата** с клавиатуры и навигация стрелками (ARIA
  combobox/listbox): панель в конце `body` не попадает в порядок Tab после
  поля, а переносить фокус вручную не стали - как и у **Поиска
  пользователя**, выбор идет щелчком.
- Закрытие по уходу фокуса из поля: щелчок по найденному **Чату** снимает
  фокус с поля раньше, чем срабатывает, и такое закрытие убило бы выбор.
- Правило совпадения названия: его задает внешнее API, спека его не обещает.
- Выделение совпадений в названиях найденных **Чатов**: от него отказались.

## Decisions

### Запрос по названию - параметр существующего `chats`, а не новый метод

`ChatGateway.chats` принимает необязательный запрос с `title`;
`ChatApi.chats` передает его в `params`, пустой запрос дает прежний `GET /chats`
без параметров. `ChatListService` зовет метод как раньше.

Альтернатива - отдельный `searchChats(title)` в шлюзе. Отвергнута: это тот же
endpoint и тот же ответ, два метода разошлись бы в маппинге и тексте ошибки.

### Вводимые сущности

| Имя                     | Слой         | Ответственность                                                                                                                                 |
| ----------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `ChatsQuery`            | application  | Необязательные параметры запроса списка **Чатов**; сейчас только `title`                                                                        |
| `SearchChatsService`    | application  | Use case **Поиска чата**: по названию отдает найденные **Чаты** через `CHAT_GATEWAY`. Состояния не держит - как `SearchUsersService`            |
| `ChatSearchStatus`      | application  | `NotStarted` / `Found` / `NothingFound` - как `UserSearchStatus`; результат `Found` несет найденные **Чаты**                                    |
| `Popover` (правка)      | shared/ui    | Новый вход режима: `'click'` (по умолчанию, как сейчас) или `'manual'` - щелчок по хосту игнорируется, `open()`/`close()` зовет владелец        |
| `createChatSearchState` | application  | Состояние **Поиска чата** из потока ввода: задержка, отмена предыдущего запроса, пустой ввод - `NotStarted` без запроса, отказ - `NothingFound` |
| `ChatSearch`            | presentation | Поле с `Popover` в ручном режиме, содержимое выпадающего списка, открытие по результату, сброс поля после выбора                                |

`ChatList` показывает `ChatSearch` между шапкой и списком только в ветке
загруженного непустого списка. Основной список, `ChatListService` и шапка
**Выбранного чата** не меняются.

### Состояние поиска - отдельная фабрика, а не обобщение `createUserSearchState`

Повторение появилось впервые, и два поиска уже расходятся: разные источник,
тип результата и имена состояний (`NobodyFound` против `NothingFound`).
Обобщать до `createSearchState<T>` имеет смысл, когда станет видно, что
действительно общее. Константа задержки дублируется осознанно.

### Выпадающий список - `Popover` в ручном режиме

Хост `Popover` - само поле **Поиска чата**, режим `'manual'`, содержимое -
шаблон `ChatSearch` со списком найденных **Чатов** или текстом
`No chats found`. Ширина содержимого - 288px, по ширине поля: панель списка
**Чатов** фиксированная, и примитиву не нужно уметь подгонять ширину под хост.

Открытие и закрытие:

- на каждом новом результате со статусом `Found` или `NothingFound`
  `ChatSearch` зовет `open()`; повторный вызов у открытой панели ничего не
  делает, поэтому продолжение ввода после Escape открывает список снова;
- на `NotStarted` (поле очищено) - `close()`;
- Escape и щелчок вне поля и панели закрывают панель силами `Popover`, текст
  остается; щелчок в поле ничего не меняет;
- найденные **Чаты** - ссылки `routerLink` на адрес **Чата**: выбор - обычная
  навигация, **Выбранный чат** по-прежнему задается адресом; щелчок по ссылке
  очищает поле, статус уходит в `NotStarted`, и панель закрывается.

`PopoverCoordinator` видит панель поиска как любую другую: ее открытие
закрывает панель **Добавления участника** в шапке, и наоборот.

Ручной режим - новый вход `Popover`, а не отдельная директива: закрытие,
позиционирование и координатор у двух режимов общие, различается только
реакция на щелчок по хосту. Режим по щелчку остается по умолчанию, поэтому
`selected-chat-header` не меняется.

Альтернативы:

- список в разметке `ChatSearch` с абсолютным позиционированием - дал бы
  порядок Tab без ручного фокуса, но завел бы второй механизм выпадающих
  панелей в проекте со своими правилами закрытия;
- `Popover` без правок на обертке поля, с `stopPropagation` щелчка в поле, -
  отвергнут: держится на внутреннем устройстве слушателя примитива.

### Тексты и вид

Доступное имя поля и плейсхолдер - `Search chats`, пустой результат -
`No chats found`. Строка найденного **Чата** - **Аватар** размера `sm` и
название, как строка найденного **Пользователя** в
`add-chat-user-panel`.
Артборды «поиск: найдены чаты» и «поиск: ничего не найдено» добавляются в
канвас экрана чатов
(https://claude.ai/code/artifact/fcd629d1-a834-4059-981c-16f2a914ca55).

### Мок-бэкенд

`GET /chats` в `mock-backend` фильтрует по `title` без учета регистра по
вхождению подстроки. e2e берет названия, которые совпадают и по началу, чтобы
не зависеть от правила реального API.

### Уровни тестов

| Сценарий спеки                                                                                                  | Уровень                                                                     |
| --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Поле видно рядом со списком; поля нет, пока искать нечего                                                       | component (`chat-list`)                                                     |
| Поиск не начат; ввод продолжился до ответа; отказ внешнего API (без **Уведомления**, следующий ввод снова ищет) | application (`chat-search.state`)                                           |
| Запрос по названию уходит с `title`, без названия - без параметров                                              | infrastructure (`chat.api`, `http-chat-gateway`)                            |
| Чаты найдены; ничего не найдено; поле очищено; закрытие по Escape; закрытие по щелчку вне; щелчок в поле        | component (`chat-search`)                                                   |
| Основной список не сужается                                                                                     | component (`chat-list`)                                                     |
| Найденный чат выбран                                                                                            | component (`chat-search`: адрес ссылки, сброс поля) + e2e (переход и шапка) |
| Все сценарии `shared-ui-popover`                                                                                | component (`popover.spec.ts`; сценарии режима по щелчку уже покрыты)        |
| Вид выпадающего списка                                                                                          | e2e `@visual`                                                               |

### ADR

Не пишем. Все решения выше легко откатить: они живут в одном компоненте,
одной фабрике и одном входе `Popover` - условие «тяжело
откатить» не выполнено.

## Risks / Trade-offs

- [`GET /chats` без `limit` может отдавать не все **Чаты**] → найденный
  **Чат** вне загруженного списка откроется без названия в шапке. Контракт
  значения по умолчанию не объявляет, проект учебный - принимаем как есть;
  если всплывет, это отдельный issue про полноту списка, а не про поиск.
- [Без выбора с клавиатуры поиск хуже доступен] → осознанно, как у **Поиска
  пользователя**; если понадобится, это правка обоих поисков сразу, а не
  только этого.
- [Панель открыта, а человек ушел из поля клавишей Tab] → панель остается
  открытой до Escape или щелчка вне; принимаем, пока выбор идет щелчком.
- [Ширина содержимого 288px завязана на ширину панели списка **Чатов**] →
  если панель станет резиновой, ширину придется брать от хоста; это правка
  `Popover`, а не поиска.
- [Отказ API неотличим от пустого результата] → осознанно, как у **Поиска
  пользователя**; следующий ввод повторяет запрос.
