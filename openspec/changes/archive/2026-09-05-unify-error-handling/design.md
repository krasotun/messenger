## Context

Мотивация - в `proposal.md`, раздел Why.

Что определяет подход:

- Каждый метод шлюза заканчивается одинаковым блоком:
  `catchError((error) => throwError(() => mapHttpError(error, fallback)))`.
  Запасное сообщение у каждого метода свое.
- У `currentSession` перед этим блоком стоит собственная ветка: ответ `401` -
  это не ошибка, а `CurrentSessionStatus.Anonymous`.
- `mapHttpError` уже умеет все, что нужно: достает `reason` из ответа, разбирает
  текстовое тело и отдельно обрабатывает истекший предел времени.

## Goals / Non-Goals

**Goals:**

- Одно место, где ошибка внешнего API превращается в **Ошибку приложения** для
  вызывающей стороны шлюза.
- Спеки шлюзов остаются без правок.

**Non-Goals:**

- Состояние use case (`status`, `errorMessage`, `isSubmitting`) не трогаем: это
  не обработка ошибок, а состояние экрана. Отдельный разговор.
- Показ ошибки в `presentation` не трогаем. Тосты - #112.
- `mapHttpError` не переписываем.

## Decisions

### Оператор в конце pipe, а не интерцептор

Вводится `toApplicationError(fallbackMessage)` - RxJS-оператор в
`@shared/errors`, слой `shared`. Ответственность: перехватить ошибку потока и
пробросить дальше **Ошибку приложения** от `mapHttpError`.

Альтернатива - HTTP-интерцептор, превращающий любой `HttpErrorResponse` в
**Ошибку приложения** централизованно. Отклонена: запасное сообщение у каждого
вызова свое, и его пришлось бы возить через `HttpContext` от шлюза к
интерцептору - то же дублирование, только длиннее. Ветка `401` в
`currentSession` при этом стала бы исключением из общего правила.

Альтернатива - базовый класс шлюза с защищенным `request(obs, fallback)`.
Отклонена: наследования в `src` сейчас нет, а по конвенции проекта отсутствие
прецедента - сигнал, что конструкция проекту чужая.

Порог `docs/adr/README.md` решение не проходит: не выполнено условие «тяжело
откатить» - переход на интерцептор позже затрагивает три файла шлюзов. ADR не
заводим.

## Уровни тестов

| Что проверяется                                                                                                           | Уровень        |
| ------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `toApplicationError`: причина из ответа, запасное сообщение, истекший предел времени, успешное значение проходит насквозь | infrastructure |
| Шлюзы отдают **Ошибку приложения**; `currentSession` на `401` отдает `Anonymous`                                          | infrastructure |

Новых сценариев нет: change ничего не добавляет к поведению. Существующие спеки
шлюзов - сеть безопасности, и они не правятся.

## Risks / Trade-offs

- Оператор скрывает `catchError`, и в шлюзе становится не видно, что поток
  вообще ловит ошибку. → Имя оператора говорит о результате
  (`toApplicationError`), а стоит он последним в `pipe` - там же, где раньше
  стоял `catchError`.
- Ветку `401` в `currentSession` легко случайно снести оператором. → Она
  остается отдельным `catchError` выше по `pipe`, и ее проверяет существующая
  спека шлюза.
