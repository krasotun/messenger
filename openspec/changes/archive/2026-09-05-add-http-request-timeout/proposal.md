## Why

У запросов к внешнему API нет предела времени: единственный интерцептор
подставляет базовый адрес и ничего не знает о продолжительности. Зависший
запрос остается в состоянии отправки до браузерного дефолта - десятки секунд,
иногда минуты, - и все это время **Флоу отправки** держит форму заблокированной,
а человек не получает ни успеха, ни ошибки.

Issue: #113

## What Changes

- Появляется общий предел времени на запрос к внешнему API. Истечение предела
  прерывает запрос и превращается в **Ошибку приложения** с собственным
  сообщением о том, что запрос не уложился во время.
- Предел настраивается: значение по умолчанию одно на все запросы, отдельный
  запрос может объявить свой. **Смена аватара** пользуется этой возможностью -
  загрузка файла законно идет дольше обычного вызова.
- `mapHttpError` учится узнавать истечение предела среди прочих отказов и
  переводит его в собственное сообщение, а не в запасное сообщение вызывающей
  стороны.
- Вызывающие стороны не меняются: для use case и экранов истечение предела
  ничем не отличается от прочих отказов.
- Не входит: повтор запроса, отмена по воле человека, индикация прогресса.

  доменов - предел времени на запрос и вид ошибки при его истечении.

## Impact

- Слой: `core` - новый интерцептор и токен предела времени рядом с
  `api-request.interceptor.ts`, подключение в `app.config.ts`.
- Слой: `shared` - `mapHttpError` в `shared/errors` узнает истечение предела и
  дает ему собственное сообщение.
- Слой: `infrastructure` - `user.api.ts` объявляет увеличенный предел для
  **Смены аватара**. Gateway'и не меняются: их `catchError` уже отдают
  **Ошибку приложения** наверх.
- Соседи: #103 (единая обработка ошибок) позже обобщит те же `catchError`;
  #112 (тосты) покажет сообщение о таймауте без правок здесь.
