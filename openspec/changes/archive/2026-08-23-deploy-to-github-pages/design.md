## Context

Приложение - статическая Angular-сборка без собственного бэкенда. Прежний
деплой: GitHub Actions ставил `ansible-core`, конфигурировал SSH по секретам
`VDS_*` и запускал `ansible/playbooks/deploy-app.yml`, который синхронизировал
`dist/messenger/browser` в `/var/www/messenger` на VDS. Nginx на сервере отдавал
статику, отвечал за HTTPS (certbot) и за SPA-fallback.

VDS уже выведен из эксплуатации, а секреты `VDS_*` удалены. Значит `deploy.yml`
в текущем виде неработоспособен, отката на прежний хостинг нет, и продакшен
недоступен до первого успешного деплоя на Pages.

GitHub Pages закрывает раздачу статики и HTTPS, но не умеет `try_files`, поэтому
поведение fallback нужно воспроизвести на уровне артефакта.

## Goals / Non-Goals

Goals:

- Публикация из того же workflow, без SSH и без внешнего сервера.
- Сохранение текущего набора проверок качества перед публикацией.
- Прямые ссылки на маршруты SPA продолжают работать.

Non-Goals:

- Собственный домен и CNAME (пока используется адрес `github.io`).
- Удаление `ansible/` и `docs/deployment/` - они остаются как архив.
- Изменение способа работы с API и cookie-сессией.

## Decisions

### Публикация через официальные Pages-actions

Используем `actions/configure-pages`, `actions/upload-pages-artifact` и
`actions/deploy-pages` вместо пуша в ветку `gh-pages`. Причина: не требуется
токен с правами на запись в репозиторий, история не засоряется артефактами
сборки, а деплой получает окружение `github-pages` с URL в интерфейсе Actions.

Workflow получает `permissions: { contents: read, pages: write, id-token: write }`
и `concurrency` с группой `pages`, чтобы параллельные пуши в `main` не
перетирали друг друга.

Альтернатива - `peaceiris/actions-gh-pages` (пуш в ветку) - отклонена: лишняя
внешняя зависимость и лишние права.

### Base href

Pages раздает проект по подпути `/messenger/`, поэтому сборка выполняется с
`--base-href /messenger/`. Angular Router строит ссылки от `<base href>`, так что
внутренняя маршрутизация (`/sign-in`, `/sign-up`) продолжает работать без правок
кода.

Локальная разработка и e2e не должны получить этот подпуть: e2e ходят на
`http://localhost:8080` и на dev-сервер. Поэтому base href задается параметром
сборки в deploy workflow (или отдельной production-конфигурацией), а не меняется
глобально в `angular.json` для всех конфигураций.

Альтернатива - hash-роутинг (`/#/sign-in`) - отклонена: портит адреса и меняет
пользовательское поведение ради обхода ограничения хостинга.

### SPA-fallback через 404.html

Pages отдает `404.html` для любого несуществующего пути с кодом 404, но с телом
этого файла. Копируем `index.html` в `404.html` внутри публикуемого артефакта:
браузер загружает приложение, и дальше маршрут разбирает Angular Router.

Компромисс: статус ответа остается `404` вместо `200`. Для учебного проекта это
приемлемо; для SEO - нет, и это отмечено как известное ограничение.

### Отключение Jekyll

В артефакт добавляется `.nojekyll`, иначе Pages пропускает файлы и каталоги,
начинающиеся с подчеркивания. Файл кладется в `public/`, чтобы попадать в сборку
штатным механизмом Angular.

### Судьба VDS

Сервер уже удален, секреты `VDS_*` тоже. Отката на прежний хостинг нет, поэтому
единственный путь восстановить продакшен - довести это изменение до успешного
деплоя. `ansible/` и `docs/deployment/` помечаются архивными, чтобы никто не
принял их за актуальный процесс: воспроизвести описанный там сервер уже нечем.

## Risks / Trade-offs

- **Продакшена нет прямо сейчас**: пока изменение не доведено до успешного
  деплоя, публичной версии приложения не существует. Откатиться некуда.
- **Cross-origin cookie**: origin меняется с `s9865e4c2.fastvps-server.com` на
  `krasotun.github.io`. API и раньше был cross-origin, но поведение cookie после
  переезда нужно проверить вручную реальным входом.
- **Публичность репозитория**: Pages на бесплатном тарифе требует публичного
  репозитория (или платного плана). Если репозиторий приватный - переезд
  блокируется.
- **404 на deep links**: описано выше, принимается сознательно.
- **Ручной шаг в настройках репозитория**: Pages source нужно переключить на
  GitHub Actions через UI - это нельзя сделать из кода.
