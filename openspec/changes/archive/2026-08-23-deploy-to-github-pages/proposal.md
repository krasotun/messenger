## Why

Приложение - статическая SPA без собственного бэкенда, но раздавалось с
арендованного VDS: деплой шел по SSH через Ansible, а сервер требовал ручного
provisioning (nginx, certbot, UFW) и переезда при смене хостинга. Эта
инфраструктура не оправдана, и VDS уже выведен из эксплуатации.

Сейчас продакшена нет: старый адрес не отвечает, а секреты `VDS_*` удалены,
поэтому текущий `deploy.yml` упадет при первом же пуше в `main`. Переносим
раздачу на GitHub Pages: деплой становится частью того же workflow, а сервер,
сертификаты и SSH-секреты перестают быть частью процесса.

Решение отменяет предыдущее (2026-08-16) о сохранении VDS и Ansible.

## What Changes

- Продакшен-хостинг переезжает с VDS на GitHub Pages по адресу
  `https://krasotun.github.io/messenger/`. **BREAKING**: прежний публичный адрес
  `https://s9865e4c2.fastvps-server.com` больше не существует.
- Workflow `deploy.yml` после сборки публикует артефакт через официальные
  Pages-actions вместо установки Ansible, настройки SSH и запуска
  `deploy-app.yml`.
- Сборка получает `base-href`, соответствующий пути проекта на Pages.
- Добавляется fallback для deep links: Pages не умеет `try_files`, поэтому
  публикуемый артефакт должен содержать `404.html`, повторяющий `index.html`.
- Ссылки на секреты `VDS_SSH_PRIVATE_KEY`, `VDS_HOST`, `VDS_USER`,
  `VDS_WEB_ROOT` удаляются из workflow: сами секреты уже удалены из репозитория.
- Каталог `ansible/` и `docs/deployment/` сохраняются, но помечаются как
  архивные: это неактуальный способ деплоя, оставленный для истории.
- `README.md` описывает новый адрес и новый процесс деплоя.

## Capabilities

### New Capabilities

- `deployment`: наблюдаемое поведение публикации приложения - откуда доступна
  продакшен-версия, когда она обновляется, как ведут себя прямые ссылки на
  внутренние маршруты и что происходит при неуспешной проверке качества.

### Modified Capabilities

Нет: пользовательские сценарии identity-access не меняются.

## Impact

- Слои приложения: изменений в `domain` / `application` / `infrastructure` /
  `presentation` нет. Затрагивается только сборка и инфраструктура доставки;
  косвенно - `core/routing` в части базового пути роутера.
- Файлы: `.github/workflows/deploy.yml`, `angular.json` (или параметры сборки),
  `public/` (`.nojekyll`), `README.md`, `docs/deployment/*`, `ansible/README`.
- Внешние системы: GitHub Pages включается в настройках репозитория (source -
  GitHub Actions). VDS выведен из эксплуатации, отката на него нет: до первого
  успешного деплоя на Pages продакшен-версия недоступна.
- Риск: продакшен-API `https://ya-praktikum.tech/api/v2` остается
  cross-origin, как и сейчас; смена origin на `krasotun.github.io` не меняет
  схему работы с cookie, но требует проверки живого входа после переезда.
