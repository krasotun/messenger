## Why

Первая настоящая модалка - форма редактирования профиля - показала, что
примитиву не хватает верстки: содержимое прилипает к краям окна, а кнопка
закрытия висит `position: absolute` в углу поверх содержимого. Заголовка у
модалки нет вовсе, поэтому выравнивать кнопку не с чем.

В change `shared-ui-modal` layout `header` / `main` / `footer` был явным
Non-Goal с оговоркой «добавим, если появится необходимость». Необходимость
появилась: ревью PR #58.

Issue: #59

## What Changes

- Модалка получает отступы по краям: содержимое не касается границ окна.
- Появляется header-строка: заголовок слева, кнопка закрытия справа, в одном
  ряду по одной базовой линии.
- Заголовок задается тем, кто открывает модалку, и остается необязательным:
  без него header показывает только кнопку закрытия.
- Заголовок связывается с окном как его имя для скринридера.

## Capabilities

### New Capabilities

Нет: поведение относится к уже существующей capability.

### Modified Capabilities

- `shared-ui-modal`: добавляется требование к внутренней верстке окна -
  отступы содержимого и header-строка с заголовком и кнопкой закрытия.

## Impact

- Слои: `shared/ui/modal` (`ModalShell`, `ModalService`), `presentation`
  домена `identity-access` - передача заголовка при открытии формы профиля.
- Обратная совместимость: заголовок необязателен, существующие вызовы
  `open()` продолжают работать без изменений.
