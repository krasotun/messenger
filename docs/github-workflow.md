# Работа с GitHub

## Issue и ветка issue

- Агент оформляет заголовок issue как `[Scope] Description`. В теле указывает
  цель, milestone и ссылку на `openspec/changes/<id>/`. Поведение и сценарии
  описывает в change. В `proposal.md` добавляет обратную ссылку `Issue: #N`.
- Агент создаёт интеграционную ветку командой
  `gh issue develop <N> --base main --checkout`. GitHub связывает ветку с issue
  в разделе Development. Проверка связи — `gh issue develop --list <N>`.

## Коммиты и заголовки PR

- Агент использует Conventional Commits для коммитов и заголовков PR.
  Описание пишет на английском, в повелительном наклонении, со строчной буквы
  и без точки в конце. Пример — `feat(users): add password change`.
- Допустимые типы и скоупы определяет [конфигурация commitlint](../commitlint.config.js).
  Скоуп необязателен. Для нового доменного скоупа агент добавляет имя каталога
  из `src/app/domains/` в `scope-enum`.
- Для ломающего изменения агент добавляет `!` перед двоеточием и футер
  `BREAKING CHANGE: ...`. Заголовок PR должен подходить для squash-коммита.

## Блок реализации

1. Агент переключается на ветку issue и обновляет её через `git pull`. От неё
   создаёт ветку `<issue>-<номер секции tasks.md>-<слаг>`, например
   `83-7-mock-backend`. Все коммиты блока идут в эту ветку.
2. Когда задачи секции выполнены, агент запускает `npm run lint` и
   `npm run test:ci`. После успешных проверок делает коммит, пушит ветку и
   открывает PR блока в ветку issue.
3. Агент перечисляет в отчёте закрытые задачи, созданные и изменённые файлы,
   результаты обеих проверок и ссылку на PR. На этом останавливается.
4. Пользователь ревьюит весь дифф PR и даёт вердикт в чате или комментарием
   в PR. Агент читает замечания через
   `gh api repos/krasotun/messenger/pulls/<PR>/comments`, добавляет исправления
   отдельным коммитом в ту же ветку и отвечает в тредах. Новые коммиты
   сохраняют привязку комментариев к строкам.
5. Пользователь мержит PR блока через squash с заголовком PR. Следующий блок
   агент начинает с шага 1 после слияния и разрешения пользователя продолжать.

## Завершение issue

Когда все блоки влиты в ветку issue, агент открывает финальный PR из неё в
`main`. Только в тело этого PR добавляет `Closes #N` и мержит его через squash.
Слияние закрывает issue.
