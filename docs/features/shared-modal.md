# [Shared UI] Modal primitive

## Goal

Приложение должно уметь открывать и закрывать модальное окно с произвольным содержимым.

## Scope

- модалка открывается с произвольным содержимым;
- сообщает наружу о своих ключевых событиях;
- в один момент активна только одна модалка;
- у модального окна три возможных размера - small, medium и large;

## Out of scope

- компонент для вставки в модалку. Пока выводим заглушку.
- переключение контента в модалке - например, для подтвержения.
- header/main/footer layout контента — добавим отдельно, если появится необходимость.

## Behavior

- располагается по центру экрана;
- при открытии блокируется скролл в приложении;
- оставшаяся часть приложения вокруг модалки затеняется;
- крестик — это отдельный, всегда присутствующий элемент модалки;
- закрытие (по крестику, Esc, backdrop, либо по сигналу из контента) — единое событие close, независимо от источника;
- клик внутри модалки не приводит к ее закрытию;
- сохранение (save) — отдельное событие от контента с данными.
- нет возможности открыть больше одной модалки; повторный вызов `open()` при активной модалке игнорируется (defensive no-op, не пользовательский сценарий);
- размер пресета это ширина, высота всегда по контенту;
- размер по умолчанию - medium;
- после закрытия overlay уничтожается (disposed).

## Test scenarios

- после открытия модалка находится в центре экрана;
- фон вокруг модалки затенен;
- при ресайзе экрана с открытой модалкой модалка остается в центре;
- при открытой модалке горизонтальный и вертикальный скролл заблокирован;
- при закрытии модалки скролл восстанавливается;
- нажатие на крестик приводит к закрытию модалки и уведомлению close;
- нажатие на ESC приводит к закрытию модалки и уведомлению close;
- сигнал закрытия из контента приводит к закрытию модалки и уведомлению close;
- клик по backdrop приводит к закрытию модалки и уведомлению close;
- клик внутри модалки не приводит к закрытию модалки и уведомлению close;
- сохранение из контента приводит к уведомлению save с переданными данными;
- нет возможности открыть более одной модалки: повторный `open()` при активной модалке не создает вторую модалку и не влияет на уже открытую;
- ширина модалки соотвествует заданному пресету (если пресет не задан - размер medium);
- высота модалки соответствует высоте контента и меняется при изменении контента;
- после закрытия модалки overlay уничтожается.

## Design notes

Реализация - singleton сервис, по методу open открывает модалку.
Состояние хранится в сервисе - сервис не дает открыть вторую модалку.
Модалка открывается через CDK Overlay. Используется shell-компонент.
CDK Overlay предоставляет события backdrop/Esc, на которые подписывается сервис и вызывает закрытие; крестик — собственный элемент shell, вызывающий закрытие explicitly.
Модалка принимает компонент через input и рендерит его как единственное содержимое.
В компонент могут передаваться любые данные для его inputs.
Компонент получает через DI ModalRef и вызывает modalRef.close()/modalRef.save(data) для уведомлений наружу.
