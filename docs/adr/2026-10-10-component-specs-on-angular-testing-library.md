# Спеки компонентов пишутся на Angular Testing Library

- Дата: 2026-10-10
- Статус: accepted
- Issue: #232

## Контекст

Каждый спек компонента заводил свои геттеры по BEM-классам и доставал дочерние
компоненты через `By.directive(...).componentInstance`: тесты писались втрое
дольше кода и знали разметку, а не поведение. Нужно было выбрать один способ
искать элементы и имитировать действия пользователя.

## Решение

Спеки компонентов пишутся на `@testing-library/angular` через точку входа
`zoneless`, действия пользователя - через `@testing-library/user-event`,
проверки - матчерами `@testing-library/jest-dom`; CDK component harness
заводится точечно, для компонента, который переиспользуется внутри другого.

## Причины

- Элемент ищется так, как его видит пользователь: по роли, имени, подписи
  поля, тексту. Так же написаны e2e на Playwright (`getByRole`), и у unit- и
  e2e-тестов один способ мышления.
- Поиск по имени проверяет и само имя: отдельные тесты на `aria-label` не
  нужны, а элемент без имени всплывает сразу (так нашлась кнопка участников в
  шапке чата).
- Точка входа `zoneless` сделана для приложений без Zone.js, как наше.
  Входы и выходы передаются через `inputBinding`/`outputBinding` самого
  Angular. Жертвуем `rerender`, `componentProviders` и вторым `render` в одном
  тесте: сервисы из `providers` компонента подменяются через
  `configureTestBed`, повторное открытие идет через `TestBed.createComponent`.
- Библиотека переносится на React и Vue: навык не привязан к Angular.

Отклонены:

- Свои хелперы поиска (`DomQueries`): повторяют библиотеку без ее расчета
  доступного имени и без user-event.
- `data-testid` как правило: атрибуты уходят в прод-разметку, у элемента
  появляется второе имя, тест не замечает пропавшую подпись.
- CDK harness для каждого компонента: по классу на компонент и асинхронный
  каждый шаг ради знания о разметке, которое переезжает в harness, а не
  исчезает.
- Основная точка входа `@testing-library/angular`: короче (`inputs`, `on`,
  `rerender`), но рассчитана на Zone.js.
